# Mockup first

The owner sees every change as a **mockup** before it is built. Code starts only after the owner's clear yes on the mockup.

## Steps

1. **Read the ask.** Read the code the change touches, so the mockup shows the app as it really is today (real labels, real numbers, real layout). Done when you can name every screen, card, picture or message the change alters.
2. **Build the mockup** as one HTML page in the scratchpad (load `artifact-design` first). Pick the form by what changes:
   - **Screen, card, picture**: the real layout in the app's look — Thai text, realistic figures, IBM Plex font, navy table header, unitclub footer on cards.
   - **Bot or chat**: the chat as the customer sees it on Messenger or LINE, before and after, with buttons and pictures in place.
   - **Nothing on screen** (data, routing, fixes): a short before/after of what the owner or customer will notice, in plain Thai.
   - **Real choices**: 2–3 options side by side, each labelled ก / ข / ค.

   Done when every item named in step 1 appears on the page.
3. **Publish** it with the Artifact tool and give the owner the link plus a 2–3 line Thai summary of what changed and any question that needs their decision.
4. **Iterate.** Apply each round of feedback to the same file and republish (same URL). Done when the owner says yes (โอเค / ได้ / ทำเลย).
5. **Build** exactly what was approved. When the built result differs from the mockup, show the difference before pushing.
