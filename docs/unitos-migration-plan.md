### กติกาอื่น

- **ล็อกอิน:** ใช้รหัส 6 หลักช่องเดียว เพราะรหัสไม่ซ้ำกันทั้งระบบ ส่วน admin ไม่ต้องยืนยันด้วย Google
- **สมาชิกใหม่ใน UnitOS:** ใช้ Studio ได้ทันที ไม่ต้องสมัครแยก
- **ตัวแทนที่ถูกลบหรือห้องที่ถูกระงับ:** ถูกเตะออกทันที เพราะระบบเช็กกับ UnitOS ทุกครั้งที่ใช้งาน
- **ห้องทดลองใช้:** ได้ Studio แต่โควตา AI ต่ำกว่าห้องที่จ่ายเงิน
- **เปิด/ปิดรายห้อง:** ทำได้ผ่านสวิตช์ใน Console ของ UnitOS
- **สิ่งที่ย้ายไปด้วย:** ตาราง `ins_*` ทั้งหมด, ตาราง studio (`projects`, `assets`, `brand_kits`, `jobs`, `job_step_cache`, `cost_entries`, `settings`) และ `model_configs`
- **สิ่งที่ไม่ย้าย:** ข้อมูลของ Maryjane (ปิดระบบไปแล้ว) และ Organizational Chart ซึ่งยังใช้ DATA2.0 ต่อ

## ระยะที่ 2: ล็อกอินผ่าน UnitOS และแบ่งสิทธิ์

เริ่มหลังระยะที่ 1 เสร็จ แผนละเอียดจะเขียนแยกอีกฉบับ

### ฝั่ง UnitOS

- ปรับ edge function `unitos-sso` (เดิมใช้กับ Maryjane) ให้ออกตั๋วเข้า advisortool
  - ตั๋วมีอายุ 60 วินาที ใช้ได้ครั้งเดียว
  - เซ็นด้วย secret ใหม่ที่ไม่ใช้ร่วมกับ UnitOS
- เปลี่ยนปุ่มเมนูที่เคยไป Maryjane ให้มาที่ advisortool
- ใช้สวิตช์ใน Console สำหรับเปิด/ปิด advisortool รายห้อง
- เพิ่ม unique index บน `agents.agent_code` ให้ฐานข้อมูลบังคับไม่ให้รหัสซ้ำข้ามห้อง

### ฝั่ง advisortool

- `/sso`: รับตั๋วจาก UnitOS
- `/login`: ช่องใส่รหัส 6 หลัก
- ด่านกั้น `/studio`, `/api/content-*` และ `/admin`
  - กันที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม
  - ปฏิทิน การโพสต์ และการเชื่อมเพจ ต้องเช็กสิทธิ์ทุกครั้ง
- หน้า "ทีมงาน" ในหลังบ้าน สำหรับเพิ่ม/ลบผู้ช่วยและติ๊กสิทธิ์
- บันทึกการทำงาน (ใครโพสต์ ตั้งเวลา แก้ เชื่อมเพจ) และแสดงในปฏิทิน
- เพิ่ม `tenant_id` / `agent_id` ในตารางที่ตัวแทนทุกห้องใช้ (`ins_content`, `ins_people`, `ins_plan_runs` ฯลฯ) และตั้งข้อมูลเดิมให้เป็นของห้อง `83g` / รหัส 015495
- โควตา AI รายคน โดยห้องทดลองใช้ได้เพดานต่ำกว่า ตัวเลขจะเสนอจากค่า AI ต่อชิ้นจริงใน `ins_usage_ledger`

- **ห้ามเปลี่ยน `ADMIN_SESSION_SECRET`:** ค่านี้เป็นกุญแจถอดรหัส AI key และ token เพจ ถ้าเปลี่ยน ต้องเชื่อมเพจและกรอก key ใหม่ทั้งหมด

## ข้อสังเกตที่เจอระหว่างทำ (นอกขอบเขตงานนี้)

- **UnitOS มีฟังก์ชันหลายตัวที่เรียกได้โดยไม่ต้องล็อกอิน** เช่น `pin_login` และ `az_gate_verify` และ admin ทุกห้องเข้าได้ด้วยรหัสที่คนอื่นอาจรู้ ควรทบทวนแยกอีกงาน
- **Bucket `sales-visits` และ `team-documents` ใน UnitClub เป็นแบบ public:** ถ้ามีข้อมูลลูกค้าอยู่ ใครมีลิงก์ก็เปิดได้
- **เอกสารใน "สอน AI" ถูกปิดทั้ง 3 ฉบับ และ FAQ ยังไม่มี embedding:** บอตจึงยังไม่ได้ใช้ความรู้จากส่วนนี้ เป็นสภาพเดิมก่อนย้าย ไม่ได้เกิดจากการย้าย
