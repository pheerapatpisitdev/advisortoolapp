# สูตรอ่าน-ดูจนจบ — สูตรการเขียนที่สองของ Studio

วันที่ 2026-10-01 · สถานะ: ออกแบบแล้ว รอตรวจ

## เป้าหมาย

เปลี่ยนคู่มือสองไฟล์ของเจ้าของให้เป็นสูตรการเขียนที่ตัวแทนเลือกได้ใน Studio แล้วมีการ์ดเช็กลิสต์บอกว่าชิ้นที่ได้ผ่านตามคู่มือแค่ไหน

- `01-คอนเทนต์เขียน-ให้คนอ่านจนจบ.md`: ช่องว่างข้อมูล, บรรทัดแรก, F-Pattern, open loop, เรื่องเล่า, processing fluency, เช็กลิสต์ก่อนโพสต์
- `02-สคริปต์วิดีโอ-ให้คนดูจนจบ.md`: 3 วินาทีแรก, โครงเวลา, pattern interrupt, ข้อความบนจอ, เหตุผลที่คนแชร์, เช็กลิสต์ก่อนถ่าย

(ไฟล์ต้นฉบับอยู่ที่ Desktop ของเจ้าของ ไม่อยู่ใน repo กฎในไฟล์ `finish.ts` คือฉบับที่ระบบใช้จริง)

## สิ่งที่ตัดสินใจแล้ว

| เรื่อง | ตัดสินใจ |
|---|---|
| รูปแบบ | เป็นสูตรใหม่ ไม่ได้เอาไปรวมกับสูตรคอนเทนต์โปร |
| เลือกร่วมกับสูตรโปร | ไม่ได้ เลือกได้ทีละสูตร เพราะกฎทับกันเกือบครึ่งและบางข้อขัดกัน |
| ใช้กับโหมดไหน | ทั้งห้าโหมด (แบบประกัน · รีวิวเคลม · หาทีม · ความรู้ · เขียนเอง) ทั้งโพสต์และสคริปต์ ยกเว้นโฆษณา และยกเว้นมุม "ตัวเลขชัดๆ" (ไม่มีตัววางแผน) เหมือนสูตรโปร |
| น้ำเสียงและเคสลูกค้า | กฎเดิมทั้งสองข้อยังใช้อยู่: น้ำเสียงเป็นกลาง ไม่มี ผม/ครับ/ค่ะ (CORE_RULES ข้อ 8) และห้ามแต่งเป็นเรื่องลูกค้าจริง (ข้อ 6) สูตร "หนึ่งคน หนึ่งฉาก" ใช้กับเรื่องจริงที่เจ้าของใส่ในช่อง `fact` หรือกับสถานการณ์สมมติที่เขียนบอกชัดว่าสมมติ |
| การ์ดเช็กลิสต์ | ใช้การตรวจแบบกลไกอย่างเดียว ไม่เรียก AI และไม่มีค่าใช้จ่าย ข้อที่ต้องใช้วิจารณญาณให้ตัวแทนติ๊กเอง |
| การ์ดขึ้นกับชิ้นไหน | เฉพาะชิ้นที่สร้างด้วยสูตรนี้ |
| ความยาวคลิป | ยังเป็น 30 / 60 / 180 เหมือนเดิม แต่ใช้โครงเวลาของคู่มือกับทุกความยาว |
| เหตุผลที่คนแชร์ | ตัววางแผนเลือกให้ทีละชิ้น (ถ้าโหมดไม่มีตัววางแผน ตัวเขียนเลือกเอง) ฟอร์มไม่มีช่องเพิ่ม |
| วิธีทำในโค้ด | เปลี่ยน `pro: boolean` เป็น `formula: "pro" \| "finish" \| null` |

## ชื่อและชนิดข้อมูล

```ts
// src/lib/content/formula.ts (ใช้ได้ทั้งฝั่งเบราว์เซอร์และเซิร์ฟเวอร์)
export type Formula = "pro" | "finish";
export const FORMULA_NAME: Record<Formula, string> = { pro: "สูตรคอนเทนต์โปร", finish: "สูตรอ่าน-ดูจนจบ" };
export function readFormula(v: unknown): Formula | null;         // รับเฉพาะ "pro" | "finish" ค่าอื่นเป็น null
export function outputFormula(o: { formula?: unknown; pro?: boolean }): Formula | null; // ชิ้นเก่าที่มี pro: true → "pro"
```

ชื่อ "สูตรอ่าน-ดูจนจบ" เป็นชื่อชั่วคราว เปลี่ยนได้ในจุดเดียวคือ `FORMULA_NAME`

## 1. กฎการเขียน — `src/lib/content/finish.ts`

วางแบบเดียวกับ `pro.ts` หัวของกฎทุกชุดเขียนไว้ว่า กฎที่ห้ามละเมิด กฎ คปภ. (POLICY_RULES_TH) และกฎ Facebook มาก่อนเสมอ
และห้ามเขียนชื่อเทคนิค (open loop, pattern interrupt ฯลฯ) ลงในชิ้นงาน

### `FINISH_HOOK_RULES` — ใช้กับตัววางแผน และตัวเขียนของโหมดที่ไม่มีตัววางแผน

- **ช่องว่างขนาดกลาง**: เปิดจากเรื่องที่คนอ่านรู้อยู่ครึ่งหนึ่ง เช่น เบี้ยที่จ่ายอยู่ บรรทัดหนึ่งในกรมธรรม์ หรือความเชื่อที่มีอยู่ แล้วเปิดปมตรงนั้น ห้ามเปิดแบบตำรา ("X คืออะไร", "ทำความเข้าใจ X")
- **เฉพาะเจาะจง**: ใช้รายละเอียดจริงหนึ่งอย่างแทนคำคุณศัพท์ มีตัวเลขได้ไม่เกิน 1 ตัว และต้องคัดลอกจากข้อมูลตรงตัว
- **ไม่ให้คนค้านในใจ**: ห้ามคำโอ้อวดที่คนอ่านจะคิดทันทีว่า "ไม่จริงหรอก"
- **ห้ามเกริ่น**: ห้ามคำทักทายหรือประโยคนำ เช่น สวัสดี, วันนี้จะมา…, หลายคนถามมาว่า…
- **สัญญาให้ชัด**: บอกว่าอ่านหรือดูจบแล้วจะได้อะไร และต้องทำได้จริงจากข้อมูลที่มี
- **กฎ Facebook**: พูดถึงกลุ่มคนแบบบุคคลที่สาม ห้ามเรียกคนอ่านว่าเป็นคนกลุ่มนั้น
- ยาวไม่เกิน `FINISH_HOOK_MAX = 80` ตัวอักษร ห้ามมีคำชวน (ทักแชท คอมเมนต์ กดติดตาม)
- เลือก **`shareWhy`** หนึ่งค่า:
  - `use`: ของใช้ได้ทันที เช่น ตัวเลข วิธีเช็ก เช็กลิสต์ที่คนอ่านเซฟไว้ใช้เองได้
  - `insider`: ความรู้วงใน คือสิ่งที่คนในวงการรู้แต่ลูกค้าไม่รู้ และต้องมาจากข้อมูลผลิตภัณฑ์
  - `voice`: พูดแทนความรู้สึกที่ลูกค้าคิดอยู่แต่ไม่กล้าพูด

  ถ้าเป้าหมายเป็น "ให้ทักแชท" ยังเลือก `shareWhy` ตามปกติ แต่เป็นเรื่องรองของชิ้นนั้น

### `finishRules(format, length, loop)` — ใช้กับตัวเขียน

**กฎที่ใช้ทั้งโพสต์และสคริปต์**
- ย่อหน้าหนึ่งมีไอเดียเดียว ขึ้นต้นย่อหน้า bullet และหัวข้อด้วยคำที่มีเนื้อหา เพราะคนกวาดตาอ่านแค่สองคำแรก
- ศัพท์เทคนิคทุกคำต้องมีคำแปลตามทันที ในวงเล็บหรือในประโยคถัดไป
- เปิดลูปอย่างน้อย 1 จุด (เช่น "เดี๋ยวบอกว่าข้อไหนพลาดบ่อยสุด") และต้องปิดทุกลูปก่อนจบ ประโยคท้ายย่อหน้าต้องพาไปย่อหน้าถัดไป
- ถ้าเล่าเป็นเรื่อง: หนึ่งคน หนึ่งฉาก ปัญหาที่จับต้องได้ เล่าตามลำดับเวลา ใช้เรื่องจริงจากเจ้าของ (`fact`) หรือเขียนบอกชัดว่าสมมติ ห้ามตั้งชื่อหรืออายุให้ตัวละครที่ไม่มีในเรื่องจริง
- ใช้ `shareWhy` ของชิ้นนั้น ถ้าเป้าหมายคือ "ให้คนเห็นเยอะ" ให้ปิดด้วยสิ่งที่คนอ่านเอาไปทำต่อเองได้โดยไม่ต้องทักมา
- ห้ามใช้ความกลัวเป็นตัวขับหลัก สิ่งที่ hook สัญญาไว้ต้องได้ครบในเนื้อหา

**กฎเฉพาะโพสต์**
- ใช้พีระมิดหัวกลับ ให้ข้อสรุปอยู่ใน hook กับต้น body ก่อนคำว่า "ดูเพิ่มเติม" (ประมาณ `FOLD` = 125 ตัวอักษร ยกมาจากสูตรโปร)
- ย่อหน้ายาวไม่เกิน 4 บรรทัดบนมือถือ ช่วงข้อความไม่เกิน 2 บรรทัด ใช้ bullet แทนย่อหน้ายาว

**กฎเฉพาะสคริปต์** (โครงเวลาเขียนตามความยาวที่เลือก)
- `30`: ใช้แม่แบบ 25 วิ: hook [0–2 วิ] → ตอบทันทีภายใน 8 วิ → ขยายด้วยตัวอย่าง 1 เรื่อง → สรุปเป็นประโยคเดียวที่จำง่าย → เหตุผลที่ควรเซฟหรือแชร์
- `60`: ใช้แม่แบบ 45 วิ: hook → ขยายความและเปิดลูป (2–5 วิ) → คุณค่าชิ้นแรกภายใน 10 วิ → เคส (ตามกฎเรื่องเล่า) → hook กลางประมาณวินาที 15 และ 30 → ปิดลูป → เหตุผลที่ควรแชร์
- `180`: เหมือน `60` และมี hook กลางทุกประมาณ 30 วิ
- เปลี่ยนภาพทุก 5–7 วิ (ขนาดภาพ มุมกล้อง ภาพแทรก ข้อความขึ้นจอ) เขียนในวงเล็บ
- ตัวเลขทุกตัวที่พูดต้องขึ้นจอเป็น `{จอ: …}` ในช่วงเดียวกัน เพราะมีคนดูแบบปิดเสียง
- หนึ่งคลิป หนึ่งประเด็น ไม่มีช่วงเงียบหรือคำเกริ่น
- ถ้า `loop` เป็นจริง ให้ใช้ `LOOP_RULES` กับการปิดท้ายแทน (ย้ายเหตุผลที่ควรแชร์ไปกลางคลิป)

### สิ่งที่ AI ต้องตอบเพิ่ม

- ตัววางแผน: `{"plans":[{"angle","hook","shareWhy"}]}`
- ตัวเขียน: ทุกชิ้นมี `"loops":[{"open":"…","close":"…"}]` คือข้อความที่คัดลอกมาจากชิ้นงานตรงตัว ถ้าเป็นโหมดที่ไม่มีตัววางแผน ให้ตอบ `"shareWhy"` มาด้วย

การ parse อยู่ใน `finish.ts`
- `parseLoops(raw, text)`: เก็บเฉพาะลูปที่ open และ close เป็นข้อความ มีอยู่จริงใน `text` และ close มาหลัง open ข้ออื่นทิ้งไป (หลักเดียวกับ `parseProof`) เก็บได้ไม่เกิน 5 ลูป
- `readShareWhy(v)`: ค่าที่รับได้คือ `"use" | "insider" | "voice"` ค่าอื่นเป็น `null`

## 2. การ์ดเช็กลิสต์ — `src/lib/content/finish-check.ts`

เป็นฟังก์ชันล้วน ไม่เรียก AI และใช้ได้ในเบราว์เซอร์ ทำหน้าที่เตือนอย่างเดียว **ไม่บล็อกการโพสต์** (หลักเดียวกับ check.ts)

```ts
export interface FinishResult {
  id: FinishCheckId;
  ok: boolean;
  /** ข้อความตรงจุดที่ไม่ผ่าน ตัดสั้น ๆ ให้รู้ว่าแก้ที่ไหน */
  where: string[];
}
export function finishChecks(out: ContentOutput, format: "post" | "script"): FinishResult[];
```

### ตรวจอัตโนมัติ

| id | ข้อ | ตรวจยังไง |
|---|---|---|
| `no-preamble` | เปิดไม่เกริ่น | hook ไม่ขึ้นต้นด้วยคำใน `PREAMBLE` (สวัสดี, วันนี้จะมา, ก่อนอื่น, หลายคนถาม, ขอเล่า ฯลฯ) |
| `hook-short` | hook สั้นพอ | ไม่เกิน `FINISH_HOOK_MAX` = 80 ตัวอักษรที่มองเห็น |
| `para-lines` | ย่อหน้าไม่เกิน 4 บรรทัดบนมือถือ | ย่อหน้าคือข้อความที่คั่นด้วยบรรทัดว่าง นับเป็นตัวอักษรที่มองเห็น ≤ 4 × `MOBILE_LINE` |
| `run-lines` | ช่วงข้อความไม่เกิน 2 บรรทัด | ช่วงคือข้อความระหว่างช่องว่างหรือขึ้นบรรทัดใหม่ ≤ 2 × `MOBILE_LINE` |
| `lead-words` | ขึ้นต้นย่อหน้าด้วยคำที่มีเนื้อหา | ย่อหน้าหรือ bullet ไม่ขึ้นต้นด้วยคำใน `WEAK_OPENERS` (เราขอแนะนำ, ซึ่ง, ทั้งนี้, อย่างไรก็ตาม, โดย, และ, ก็ ฯลฯ) |
| `jargon` | ศัพท์เทคนิคมีคำแปล | คำใน `JARGON` (IRR, co-payment/co-pay, deductible, annuity, rider, Unit Linked ฯลฯ ไม่สนตัวพิมพ์เล็กใหญ่) ต้องมี `(` หรือคำว่า คือ/หมายถึง/แปลว่า/หรือ ตามหลังภายใน 30 ตัวอักษร |
| `list-count` | hook บอกกี่ข้อ เนื้อหามีครบ | hook มีรูป "N ข้อ / N เรื่อง / N จุด / N อย่าง" แล้ว body ต้องมีข้อขึ้นต้น 1 ถึง N ถ้า hook ไม่ได้บอกจำนวน ข้อนี้ผ่าน |
| `loops-closed` | ลูปปิดครบ | ทุกข้อใน `out.loops` ต้องยังพบ open และ close ในข้อความปัจจุบัน และ close ต้องมาหลัง open ถ้าไม่มี `loops` เลย ข้อนี้ไม่ผ่าน `where` บอกว่า "ไม่มีข้อมูลลูป ตรวจเองนะครับ" |
| `numbers-on-screen` | (สคริปต์) ตัวเลขที่พูดขึ้นจอ | ใช้ `scenes()` เดิม: ตัวเลขใน `say` ของแต่ละช่วงต้องอยู่ใน `screen` ของช่วงเดียวกัน เทียบด้วย `numbersIn()` จาก check.ts |
| `cuts` | (สคริปต์) เปลี่ยนภาพสม่ำเสมอ | ช่วงที่ยาวเกิน 7 วิ (อ่านจากเวลาในวงเล็บเหลี่ยม) ต้องมี `acts` อย่างน้อย 1 อย่าง |

- **ตัวอักษรที่มองเห็น**: นับ code point โดยไม่นับสระบน สระล่าง และวรรณยุกต์ไทย (U+0E31, U+0E34–U+0E3A, U+0E47–U+0E4E)
- **`MOBILE_LINE` = 36** ค่าเริ่มต้นนี้จะปรับด้วยตัวอย่างจริงในเทสต์ แล้วเขียนเหตุผลไว้ในคอมเมนต์
- รายการ `PREAMBLE`, `WEAK_OPENERS` และ `JARGON` อยู่ในไฟล์นี้ ยังไม่เปิดให้แก้ผ่านหน้าแอดมิน

### ข้อที่ตัวแทนติ๊กเอง

| id | ข้อ |
|---|---|
| `lead-first` | โพสต์: ข้อสรุปอยู่ต้นเรื่อง · สคริปต์: ส่งคุณค่าชิ้นแรกภายใน 10 วิ |
| `promise-kept` | hook สัญญาอะไร เนื้อหาให้ครบ |
| `share-reason` | มีเหตุผลให้คนแชร์ (การ์ดแสดง `shareWhy` ของชิ้นนั้น) |
| `one-scene` | ถ้าเป็นเรื่องเล่า ต้องเป็นหนึ่งคน หนึ่งฉาก |
| `no-fear` | ไม่ใช้ความกลัวเป็นตัวขับหลัก |
| `old-client` | ถ้าลูกค้าเก่าอ่านเจอ เขาจะยังไว้ใจเราเหมือนเดิม |
| `muted` | (สคริปต์) ดูแบบปิดเสียงแล้วยังเข้าใจ |

ข้อที่ติ๊กเก็บใน `output.finishTicks: string[]` ผ่าน `saveOutput(id, output)` แบบไม่ส่ง flags เพราะการติ๊กไม่ได้แก้ข้อความ จึงไม่ต้องตรวจตัวเลขซ้ำ

  - ให้เลือก "สูตรการเขียน" ได้สามแบบ: ไม่ใช้ / สูตรคอนเทนต์โปร (13 ข้อ) / สูตรอ่าน-ดูจนจบ
  - แต่ละสูตรพับดูรายการกฎได้
  - ขนาดปุ่มกดอย่างน้อย 44px (min-h-11) เหมือนปุ่มอื่นใน Studio
  - ถ้าเลือกรูปแบบโฆษณา จะไม่มีตัวเลือกนี้
- **`useFormula()`** มาแทน `usePro()` จำตัวเลือกต่อเบราว์เซอร์ด้วย key `content-formula` ถ้าไม่มี key นี้แต่มี `content-pro = on` ให้เริ่มที่ `"pro"`
- **PieceCard / ScriptCard**: ป้ายเดิม "สูตรโปร" เปลี่ยนเป็นชื่อสูตรตาม `outputFormula()` ถ้าเป็นสูตรอ่าน-ดูจนจบ ต่อท้ายด้วย "ตรวจ 8/10"
- **PieceEditor**: การ์ดเช็กลิสต์อยู่ใต้แถบคำเตือนเดิม หัวการ์ดเป็น "ตรวจอัตโนมัติผ่าน x/y · ติ๊กแล้ว a/b" ข้อที่ไม่ผ่านแสดง `where` คำนวณใหม่จากข้อความที่กำลังแก้ ไม่ต้องรอบันทึก

## 4. การไหลของข้อมูล

```
ฟอร์ม (formula) ─→ actions.ts / /api/content-claim ─→ readFormula()
   ├─ แบบประกัน: plan(… formula) ─→ FINISH_HOOK_RULES ─→ plans[].shareWhy
   │             buildMessages(… formula) ─→ finishRules() ─→ pieces[].loops
   └─ ไม่มีตัววางแผน (claim / recruit / knowledge / draft): ตัวเขียนได้ FINISH_HOOK_RULES + finishRules()
                                                          ─→ loops + shareWhy
─→ output { formula, shareWhy, loops } ─→ บันทึกเหมือนเดิม (ins_content.output jsonb)
─→ PieceEditor: finishChecks(output) + finishTicks
```

- ทุกจุดที่ตอนนี้อ่าน `pro` จะเปลี่ยนไปใช้ `formula`: `actions.ts`, `api/content-claim/route.ts`, `one-call-run.ts`, `claim-run.ts`, `recruit-run.ts`, `knowledge-run.ts`, `draft-run.ts`, `plan.ts`, `prompt.ts`, `claim.ts`, `recruit.ts`, `knowledge.ts`, `draft.ts`, `PieceCard.tsx`, `ScriptCard.tsx` และฟอร์มทั้งห้า (`ContentStudio`, `ClaimTools`, `RecruitTools`, `KnowledgeTools`, `DraftTools`)
- `ContentOutput` เพิ่ม `formula?: Formula`, `shareWhy?: ShareWhy`, `loops?: Loop[]` และ `finishTicks?: string[]`
- `pro?: boolean` ยังอยู่ในชนิดข้อมูลเพื่ออ่านชิ้นเก่า ชิ้นใหม่เขียนแต่ `formula`
- **ไม่ต้องทำ migration**

## 5. กรณีผิดพลาด

- AI ไม่ตอบ `loops` หรือ `shareWhy` หรือตอบผิดรูป: ชิ้นงานยังบันทึกได้ตามปกติ ข้อ `loops-closed` ไม่ผ่านพร้อมข้อความให้ตรวจเอง ส่วน `shareWhy` แสดงเป็น "ไม่ระบุ"
- ลูปที่ข้อความไม่ตรงกับชิ้นงานถูกทิ้งตอน parse
- ถ้า `formula` ที่ส่งมาทาง API ไม่ใช่ค่าที่รู้จัก จะถือว่าเป็น `null` (ไม่ใช้สูตร) ไม่ขึ้น error

## 6. ค่าใช้จ่าย

- คำสั่งของตัววางแผนและตัวเขียนยาวขึ้นประมาณเท่าสูตรโปร ซึ่งสูตรนี้มาแทน ไม่ได้ใช้ซ้อนกัน จึงไม่เพิ่มการเรียก AI
- การ์ดเช็กลิสต์ไม่มีค่าใช้จ่าย
- ตอนทดลองบนเบราว์เซอร์ให้จดค่าใช้จ่ายต่อชิ้นเทียบกับสูตรโปร แล้วใส่ไว้ใน commit
