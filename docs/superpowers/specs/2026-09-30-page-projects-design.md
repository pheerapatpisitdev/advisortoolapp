# ชิ้นงานเป็นโปรเจคของแต่ละเพจ — design

วันที่: 2026-09-30 · เจ้าของอนุมัติในแชท (ส่วนที่ 1 และ 2: "Ok")

## เป้าหมาย

Organic Studio (`/studio/write`) ตอนนี้เป็นกองเดียว: ทีมงานเห็นร่าง/ใช้จริง/ถังขยะของทุกเพจรวมกัน ไม่ว่าเปิดมาจากการ์ดเพจไหน
และชิ้นงานมีเพจก็ต่อเมื่อลงหรือตั้งเวลาแล้ว ให้แต่ละเพจเป็นโปรเจคของตัวเอง — เพจใครเพจมัน

## สิ่งที่ตกลงกัน

| เรื่อง | ตัดสินใจ |
|---|---|
| ชิ้นงานเป็นของเพจเมื่อไร | ตั้งแต่สร้าง — สร้างในโปรเจคเพจไหน เป็นของเพจนั้น |
| ย้าย/ทำสำเนาไปเพจอื่น | ไม่มี ชิ้นของเพจไหนลงได้เฉพาะเพจนั้น (ใช้ที่อื่นให้คัดลอกข้อความไปทำใหม่เอง) |
| ชิ้นเดิมที่เคยลง/ตั้งเวลาแล้ว | อยู่โปรเจคของเพจที่ลงไป (`fb_page_id`) |
| 2 ชิ้นหาทีมที่ยังไม่มีเพจ | ไป LuckyPlanner โชคดีที่มีแพลน (105982528649026) |
| ใครเห็นโปรเจคไหน | ตามเพจที่ดูแล (`myPages()`, 2026-09-29): เจ้าของ/แอดมิน ทุกเพจ; ทีมงาน เฉพาะที่ผูก; ทุกคนที่ดูแลเพจเดียวกันเห็นกองเดียวกัน |
| ตัวแทนที่ไม่มีเพจ | เหมือนเดิม — กองเดียวของตัวเอง |
| เพจที่ตัดการเชื่อมต่อแล้ว | ชิ้นของเพจนั้นไม่แสดงที่ไหน จนกว่าจะเชื่อมใหม่ (ไม่ลบ) |
| ไม่เปลี่ยน | คลังสูตรประโยคเปิด · งบ/โควตา AI · คลังบุคคล (แยกตามเพจอยู่แล้ว) · ชิ้นที่ลง/ตั้งเวลาแล้ว |

## สิ่งที่ผู้ใช้เห็น

- **หน้าเขียนงาน** เปิดเป็นโปรเจคของเพจเดียว (จากการ์ดบน `/studio`; ไม่ระบุ = เพจแรก เหมือนเดิม) หัวหน้าบอกชื่อเพจ
  ไม่มีตัวสลับ — เปลี่ยนเพจที่ `/studio` (owner, 2026-09-28) แท็บ รอตรวจ/ใช้จริง/ถังขยะ จำนวน และโหลดเพิ่ม เฉพาะของเพจนั้น
  ชิ้นใหม่จากทุกฟอร์ม (แบบประกัน · รีวิวเคลม · หาทีม · ความรู้ · เขียนเอง) เป็นของเพจนั้น
- **ลงเพจ** ลงได้เฉพาะเพจของชิ้นนั้น: ตัวเลือกเพจใน PublishPanel และใน "ตั้งเวลาหลายชิ้น" เปลี่ยนเป็นชื่อเพจ
  ชิ้นที่ยังไม่มีเพจ (ของเก่า) ยังเลือกเพจได้ และเป็นของเพจที่ลง ตอนที่ลง
- **ปฏิทิน** แถบรอลงของเพจ X แสดงเฉพาะชิ้นของ X (การ์ดที่วางแล้วแยกตามเพจอยู่แล้ว)
- **หน้ารวม `/studio`** ช่อง Organic Studio บนการ์ดแต่ละเพจนับร่างของเพจนั้นเอง

## การทำงาน

### ข้อมูล — `supabase/migrations/20260930_content_page.sql`

```sql
alter table public.ins_content add column if not exists page_id text;
-- a piece already on a Page, or held for one, is that Page's
update public.ins_content set page_id = fb_page_id where page_id is null and fb_page_id is not null;
-- the staff's pieces on no Page yet (two หาทีม pieces, 2026-09-30): LuckyPlanner's, the owner's call
update public.ins_content set page_id = '105982528649026'
  where page_id is null and agent_id in (select agent_id from public.ins_staff);
create index if not exists ins_content_page_status on public.ins_content (page_id, status, created_at desc);
```

`page_id` = โปรเจคของชิ้น · `fb_page_id` = เพจที่ส่งไปจริง (ความหมายเดิม) — หลังจากนี้สองค่าตรงกันเสมอเมื่อมีทั้งคู่

### ใครเห็นชิ้นไหน — `src/lib/auth/scope.ts`

- `Scope` เพิ่ม `pages: string[] | null` = เพจที่ผู้ขอเห็นได้ (`myPageIds()`); `null` = ทุกเพจ (`ALL`, งาน `after()`); `NONE` = `[]`
  อ่านไม่ได้ = `[]` (ปิดไว้ก่อน ไม่ใช่เปิด)
- ชิ้นที่มี `page_id`: เห็นเมื่อ `page_id ∈ pages` · ชิ้นที่ไม่มี: กติกาเดิมตาม `agent_id`
- `maySeePiece(scope, item)` และตัวกรอง PostgREST ตัวเดียวกัน:
  `page_id.in.(…),and(page_id.is.null,or(<กติกา agent เดิม>))` — ใช้ใน `getContent`, `listContent`, `countByStatus`, `listWaiting`
  ทุกทางที่แก้/วาด/ทิ้ง/ลง/ยกเลิกคิว ผ่าน `getContent` จึงถูกปิดด้วย
- คลังบุคคลไม่ใช้กติกานี้ (มี `visibleTo` ของตัวเอง)

### โปรเจคของคำขอ — `projectPage(asked)`

- ผู้ขอมีเพจ (`myPages()` ไม่ว่าง — รวมแอดมินที่ไม่ได้ลงโพสต์ เพื่อไม่ให้ใครได้กองรวมหลายเพจ): `asked` ถ้าอยู่ในนั้น;
  ไม่ระบุ = เพจแรก; ระบุเพจที่ไม่ได้ดูแล = ปฏิเสธ
- ผู้ขอไม่มีเพจ: `null`
- `StudioPage` เลือกโปรเจคด้วยกติกาเดียวกัน (ไม่ใช่เฉพาะคนลงโพสต์อย่างตอนนี้)

### สร้าง

- ทุกทางสร้าง (`generateContent`, `generateRecruit`, `generateKnowledge`, `generateDraft`, `/api/content-claim`, `/api/content-recruit`)
  รับ `page` อยู่แล้ว (ตอนนี้ส่งเฉพาะเมื่อมีโลโก้) → หน้าจอส่งเพจของโปรเจคทุกครั้ง
- server เรียก `projectPage(page)` ก่อนหักโควตาหรือจองงบ; ปฏิเสธ = ไม่เสียอะไร
- `saveContent` รับ `pageId` แล้วบันทึก `page_id`

### รายการ

- `listContent` / `countByStatus` / `contentWorkbench` รับ `page`: มีค่า → `page_id = page`; ว่าง (ไม่มีเพจ) → ตามขอบเขตอย่างเดียว
  `contentWorkbench` เรียก `projectPage` เอง — หน้าจอส่งเพจอื่นมาไม่ได้
- `listWaiting(page)` สำหรับแถบรอลงในปฏิทิน
- `countDraftsByPage()` ครั้งเดียวสำหรับทุกการ์ดบน `/studio` → `HomeInput.draftsByPage`

### ลงเพจ — `src/lib/content/publish-flow.ts`

- `clear()`: ชิ้นมี `page_id` และไม่ตรงกับ `input.pageId` → `{ ok:false, error: "ชิ้นนี้เป็นของเพจ <ชื่อ> — ลงได้เฉพาะเพจของตัวเอง" }`
  (ครอบ ลงเลย · ตั้งเวลา · ย้าย · ตั้งเวลาหลายชิ้น · ลากลงปฏิทิน)
- ชิ้นที่ไม่มี `page_id`: ลงได้ทุกเพจที่ดูแล และบันทึก `page_id` = เพจที่ลง ก่อนส่งไป Facebook

### หน้าจอ

- `StudioPage` ส่ง `project: { pageId, pageName } | null` ให้ `ContentStudio` (แทน `page` เดิมที่ใช้จำเพจสำหรับลงเพจ)
- `ContentStudio`: หัวบอกชื่อเพจ; รอบสร้างทุกฟอร์มส่ง `page: project.pageId`; เรียก `contentWorkbench` พร้อมเพจ;
  "ตั้งเวลาหลายชิ้น" ใช้เพจของโปรเจค ไม่มีตัวเลือก
- `PublishPanel`: ชิ้นที่มีเพจแสดงชื่อเพจแทนตัวเลือก
- `/studio` และ `calendar/page.tsx` ตามที่ว่าไว้ด้านบน
