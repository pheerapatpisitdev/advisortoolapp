# ยิงแอด Facebook จาก Studio — รอบแรก

สถานะ: spec รอเจ้าของตรวจ ยังไม่เขียนโค้ด และยังไม่ยิงแอดจริง
เป็นรอบแรกของ [studio-ad-creation-plan.md](../../studio-ad-creation-plan.md) ซึ่งเป็นแผนใหญ่ทั้งชุด
ขั้นตอนขอสิทธิ์ที่เจ้าของกดเองอยู่ใน [ads-manage-permission.md](../../ads-manage-permission.md)

## เป้าหมาย

เจ้าของเปิด `/studio/ads` เลือกชิ้นชนิด "ad" ที่มีอยู่ใน Studio กรอกลิงก์ปลายทาง งบต่อวัน และเพจ
แล้วได้แอดรูปเดียวบนบัญชีโฆษณาจริง สถานะหยุด (PAUSED) พร้อมให้กดเปิดใช้แยกอีกครั้ง
ไม่ต้องไปกรอกซ้ำที่ Ads Manager

สำเร็จเมื่อ: แอดหนึ่งตัวถูกสร้างครบสี่ขั้นบนบัญชีโฆษณาจริง ขึ้นใน Ads Manager เป็น PAUSED
และ `ad_id` ผูกกลับกับชิ้นต้นทาง ให้หน้า `/admin/ads` อ่านผลจับคู่ได้

## ขอบเขตรอบนี้

มี
- ชนิดโฆษณา: รูปเดียว (โปสเตอร์ของชิ้นนั้น)
- วัตถุประสงค์: ทราฟฟิก (`OUTCOME_TRAFFIC`)
- ปุ่ม Click-to-Website ไปลิงก์ที่กรอก
- ผู้ใช้: เจ้าของ (`owner`) คนเดียว ทั้งเชื่อมบัญชีและสร้างแอด
- ปุ่มเปิดใช้แยกจากปุ่มบันทึก

ไม่มี (รอบถัดไป)
- วิดีโอ คารูเซล คอลเลกชัน Instant Experience แคตตาล็อก
- วัตถุประสงค์ลีด คอนเวอร์ชัน และอื่น ๆ ในแผนใหญ่
- การเลือกตำแหน่งแสดงเอง (ใช้ Advantage+ placements คือไม่ส่งตำแหน่ง)
- ตัวแทนและผู้ช่วยสร้างแอด
- system user ถาวร

## ที่มาของเนื้อหาแอด

ชิ้นชนิด "ad" ใน `ins_content` (migration `20260924_content_ads.sql`) เก็บ headline ที่ `hooks[0]`
primary text ที่ `body` description ที่ `closing` และมีโปสเตอร์ ผ่านเช็กกฎ Facebook แล้ว
ฟอร์มดึงสามช่องนี้มาให้ แก้ได้ก่อนส่ง และใช้โปสเตอร์ที่เรนเดอร์แล้วเป็นรูปของครีเอทีฟ ไม่วาดใหม่
ข้อความบนโปสเตอร์ไม่ถูกส่งซ้ำเป็นข้อความโฆษณา

## การเชื่อมสิทธิ์

- เพิ่มวัตถุประสงค์ล็อกอิน `ads-manage` ใน `src/lib/facebook/oauth.ts` ใช้ config จาก `FB_ADS_MANAGE_CONFIG_ID`
  ตัวแปรว่าง = ปุ่มเชื่อมกดไม่ได้และบอกว่าขาดอะไร ไม่ตกไปใช้ `FB_LOGIN_CONFIG_ID` หรือ `FB_ADS_LOGIN_CONFIG_ID`
- config ตัวที่สาม **Ads manage** (`1083148447943779`) ติ๊กสิทธิ์ 9 ตัวเท่ากับ config เพจ Messenger bot ทุกตัว (รวม `ads_management` ที่ Messenger bot มีอยู่แล้ว) รายการอยู่ใน `docs/ads-manage-permission.md`
  เพราะการล็อกอินธุรกิจทับสิทธิ์ทั้งชุด สิทธิ์ที่ไม่ติ๊กจะถูกถอด (ขาด `pages_messaging` อินบ็อกซ์ของบอทหลุด ขาด `ads_read` หน้าอ่านผลพัง) โทเค็นแบบผู้ใช้เลือกสินทรัพย์ใน config ไม่ได้ ให้ติ๊กทุกเพจในหน้าต่างล็อกอินตอนกดเชื่อม
  `ADS_MANAGE_SCOPES` ในโค้ดสร้างจาก `SCOPES` บวกสองตัวนั้น ห้ามแก้ config เพจและ config อ่านผล
- ถ้าล็อกอินกลับมาโดยไม่มี `pages_messaging` callback ยังเก็บการเชื่อมไว้ แต่ redirect พร้อม `warn=pages` และ `/studio/ads` ขึ้นคำเตือนให้เชื่อมเพจใหม่ที่ `/admin/messenger`
- `src/app/api/facebook/connect/callback/route.ts` เพิ่มกิ่งใหม่ แยกจากกิ่งเพจและกิ่ง `ads_read` ที่ไม่แตะ
  ตรวจว่าได้ `ads_management` จริง ไม่ได้ = `noscope` ใช้ได้เฉพาะ `owner` และบันทึก audit
- โทเค็นผู้ใช้เก็บในตาราง `ins_channel_auth` ใต้คีย์ `facebook_ads_manage:act_…` (prefix ใหม่ใน `keys.ts`)
  เข้ารหัสด้วย RPC เดิม ไม่ทับแถว `facebook_ads:` ของ `ads_read`
  แถวเพจและแถวบัญชีโฆษณาเดิมต้องไม่โผล่ปนกัน (ดูเหตุผลของ prefix ใน `keys.ts`)
- โทเค็นอายุราว 60 วัน หน้าแสดงวันหมดอายุ (`tokenExpiry`) และเตือนก่อนหมด

## การสร้างแอด

server action ใน Studio (ไม่เปิด API สาธารณะ) ทำสี่ขั้นต่อเนื่องในคำขอเดียว ใช้ Graph `v23.0` เหมือน `src/lib/ads/sync.ts`

1. `POST /act_{id}/campaigns` วัตถุประสงค์ `OUTCOME_TRAFFIC` สถานะ PAUSED
2. `POST /act_{id}/adsets` งบรายวัน พื้นที่ (ค่าเริ่มต้นประเทศไทย) สถานะ PAUSED
3. อัปโหลดรูปจากโปสเตอร์ แล้ว `POST /act_{id}/adcreatives` ปุ่ม Click-to-Website ชี้ไปลิงก์ที่กรอก
4. `POST /act_{id}/ads` ผูกครีเอทีฟกับชุดโฆษณา สถานะ PAUSED

ลิงก์ว่างบันทึกไม่ได้ ขั้นใดพัง หยุดและบอกขั้นที่พัง ไม่สร้างขั้นถัดไปทับ

### ข้อมูล: `ins_ad_launch`

หนึ่งแถวต่อหนึ่งความพยายาม: piece id, บัญชีโฆษณา, เพจ, ไอดี campaign / adset / creative / ad,
ขั้นล่าสุดที่สำเร็จ, ข้อความผิดพลาด, เวลา ต้องมี migration ใหม่ (รันก่อน push ตามขั้นตอน production)
ลองใหม่ = ทำต่อจากขั้นที่พัง ใช้ไอดีที่เก็บไว้ ไม่สร้างซ้ำ

## ป้องกันเงิน

- ทุกขั้นสร้างเป็น PAUSED ปุ่มบันทึกไม่ยิงเงิน
- ปุ่มเปิดใช้เป็นการกดยืนยันครั้งที่สอง แสดงบัญชี เพจ และงบต่อวันก่อน
- เพดานงบต่อวัน ค่าเริ่มต้น 500 บาทกำหนดในโค้ด ปรับผ่าน env ฟอร์มรับค่าเกินเพดานไม่ได้
- ชิ้นเดียวกับบัญชีเดียวกันสร้างได้หนึ่งครั้ง สร้างซ้ำต้องกดยืนยันว่าตั้งใจ
- การเชื่อม การสร้าง และการเปิดใช้บันทึก audit ทุกครั้ง
- หน่วยงบแปลงตามหน่วยย่อยของสกุลเงินบัญชีที่ Meta ใช้ ตรวจกับบัญชีจริงตอนลงมือ

## ข้อผิดพลาด

- ขั้นพัง: แสดงชื่อขั้นกับข้อความจาก Meta ปุ่มลองใหม่ทำต่อจากขั้นนั้น
- โทเค็นหมดอายุ (error 190): ข้อความให้เชื่อมใหม่ แบบเดียวกับ `EXPIRED` ใน `src/lib/ads/sync.ts`
- Meta ปฏิเสธเพราะนโยบายหลังสร้าง: แสดง `effective_status` ของแอดบนหน้า ไม่ปิดเงียบ

## การทดสอบ

- ตรรกะแปลงงบและตรวจเพดาน, ลำดับสี่ขั้น, การทำต่อจากขั้นที่พัง, การไม่สร้างซ้ำ: unit test โดยจำลอง Graph
- กิ่ง callback ใหม่: ทดสอบว่าไม่แตะกิ่งเพจและกิ่ง `ads_read`
- การยิงจริงครั้งแรก: เจ้าของทดสอบเองบนบัญชีจริงด้วยงบต่ำสุด ผมไม่กดเปิดใช้ให้

## สิ่งที่ต้องยืนยันก่อนลงมือ

- เจ้าของสร้าง config ตัวที่สามและใส่ `FB_ADS_MANAGE_CONFIG_ID` ใน `.env.local` และ Vercel ตามเอกสารสิทธิ์ (`.env.example` ที่ commit แล้วยังไม่มีบรรทัดนี้ ต้องเพิ่มเอง)
- หลังล็อกอินครั้งแรกด้วย config นี้ เปิด `/admin/messenger` ตรวจว่าทุกเพจยังรับและตอบข้อความได้ ก่อนสร้างแอดใดๆ
- เพดาน 500 บาทต่อวันเป็นตัวเลขที่เจ้าของต้องการ
- ครีเอทีฟที่สร้างด้วยโทเค็นผู้ใช้ใช้เพจที่ผู้ใช้มีบทบาทอยู่ได้โดยไม่มี `pages_manage_ads` หรือไม่ (แอปยังเลือกสิทธิ์นี้ไม่ได้) ตรวจตอนลองยิงครั้งแรก
