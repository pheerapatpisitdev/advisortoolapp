# Ads Studio — แคมเปญแอดแยกจาก Organic Studio

สถานะ: spec รอเจ้าของตรวจ ยังไม่เขียนโค้ด
ต่อจากการยิงแอดรอบแรก ([2026-10-04-studio-ad-launch-v1-design.md](2026-10-04-studio-ad-launch-v1-design.md)) ซึ่งขึ้นโปรดักชันแล้ว
ดูตัวอย่างจาก Monoko (AD Studio ของแบรนด์ luckyplanner) เมื่อ 2026-10-04

## เป้าหมาย

แอดเป็นห้องของตัวเองชื่อ **Ads Studio** แยกจาก Organic Studio
เขียนคำโฆษณา ทำโปสเตอร์ และยิงแอด จบในห้องเดียว จัดเป็นแคมเปญ หนึ่งแคมเปญต่อหนึ่งแบบประกันของเพจ
ใช้ได้เฉพาะเจ้าของ (รหัส 015495) คนเดียว

สำเร็จเมื่อ:
- Organic Studio เหลือ โพสต์ กับ สคริปต์ ไม่มีแอดปน
- การ์ดเพจในหน้ารวมมีช่อง Ads Studio เฉพาะเจ้าของ
- เจ้าของสร้างแคมเปญ เขียนแอดหลายแบบ แก้โปสเตอร์ และยิงแอดจากการ์ดในแคมเปญได้
- ชิ้นแอดเก่าทุกชิ้นที่มีเพจอยู่ในแคมเปญ

## ขอบเขต

มี
- ทางเข้าจากหน้ารวมและเมนู, หน้ารายการแคมเปญ, ห้องทำงานแคมเปญ, หน้าแก้แอด
- ตาราง `ins_ad_campaign` และคอลัมน์ `campaign_id` บน `ins_content` พร้อมย้ายชิ้นแอดเก่า
- ถอดชนิด "โฆษณา" ออกจาก Organic Studio

ไม่มี
- มิติแบบ Monoko (ฮุก × บุคคล × สไตล์ภาพ) ใช้ตาราง มุมขาย × โทน ตัวเดิม
- carousel, อัตราส่วนภาพอื่นนอกจาก 1:1
- หน้าคุมผลแอดแบบ AD Pilot
- ลบแคมเปญ (ใช้ถังขยะกับชิ้นแอด)
- ให้คนอื่นนอกจากเจ้าของเข้า Ads Studio

## 1. ทางเข้า และหน้ารายการแคมเปญ

หน้ารวม Studio: การ์ดแต่ละเพจมีช่อง **Ads Studio** ถัดจาก Organic Studio เฉพาะเจ้าของ
สถานะใต้ชื่อช่อง เช่น "2 แคมเปญ · ยิงแล้ว 3" หรือ "ยังไม่มีแคมเปญ"
ลิงก์ไป `/studio/ads?page=<pageId>`

เมนูซ้าย: เปลี่ยน "ยิงแอด" เป็น **Ads Studio** ยังโผล่เฉพาะเจ้าของ

Organic Studio: ช่อง "ทำอะไร" เหลือ โพสต์ กับ สคริปต์
รายการชิ้นงาน ตัวนับร่างบนการ์ดหน้ารวม และปฏิทิน ไม่นับชิ้นชนิด "ad"

หน้ารายการ `/studio/ads?page=…`
- หัวหน้า: ชื่อเพจ ปุ่ม **สร้างแคมเปญ** ทางขวา
- แถบเล็กบอกบัญชีโฆษณาที่เชื่อมอยู่ (เช่น LuckyPlanner · THB) และปุ่มเชื่อมใหม่ แทนกล่องใหญ่ของหน้าเดิม รายการบัญชีที่รอเลือกหลังล็อกอินยังแสดงที่นี่
- การ์ดแคมเปญ: โปสเตอร์ชิ้นล่าสุด ชื่อแคมเปญ ตัวนับ ร่าง / ยิงแล้ว / เปิดใช้
- ไม่มีแคมเปญ: ขั้นตอน 1-2-3 และปุ่มเริ่ม
- ไม่ส่ง `page` มา: ใช้เพจแรกที่เชื่อมไว้ และมีตัวเลือกเพจให้สลับไปเพจไหนก็ได้

สร้างแคมเปญ: ฟอร์มสั้น เลือกแบบประกัน ชื่อ (ไม่บังคับ) จำนวนมุมขาย × โทน โทนสีโปสเตอร์
กดแล้วไปห้องทำงานแคมเปญ และเริ่มเขียนแอดชุดแรก

## 2. ห้องทำงานแคมเปญ `/studio/ads/[id]`

สองฝั่ง บนมือถือเรียงบนลงล่าง

ซ้าย แผงตั้งค่า พับได้
- แบบประกัน (ตั้งตอนสร้าง แก้ไม่ได้)
- จำนวนมุมขาย × โทน, โทนสีโปสเตอร์, ช่อง "สิ่งที่อยากเน้น" (ส่งเป็น hint ให้ตัวเขียน)
- ปุ่ม **เขียนแอดเพิ่ม N แบบ** ติดล่างแผง

ขวา การ์ดแอดเป็นตาราง
- แท็บ **ร่าง / ยิงแล้ว / เปิดใช้ / ถังขยะ** พร้อมตัวนับ
  - ร่าง: ไม่มีแถว `ins_ad_launch` ที่ยังใช้อยู่
  - ยิงแล้ว: มีแถว ยังไม่ `activated_at` รวมแถวที่ไปไม่ครบสี่ขั้น (ป้ายแดงบอกขั้นที่พัง)
  - เปิดใช้: `activated_at` มีค่า
  - ถังขยะ: ชิ้นสถานะ `trashed`
- การ์ด: โปสเตอร์ 1:1 หัวข้อ ข้อความหลัก 125 ตัวแรก ป้ายมุมขาย · โทน ป้ายเตือนกฎ Facebook

กดการ์ด เปิดหน้าแก้แอดเต็มจอ
- ซ้าย: ตัวแก้โปสเตอร์ `PosterPanel` ตัวเดิม พร้อมวาดรูปพื้นหลัง (`drawBackground`)
- ขวา: ช่องหัวข้อ / ข้อความหลัก / คำอธิบาย นับตาม `AD_LIMITS` (แดงเมื่อเกิน ไม่ตัด) ตัวอย่างแอดในฟีด Facebook ที่ตามสิ่งที่พิมพ์ ปุ่มบันทึก
- ส่วนยิงล่างขวา: บัญชีโฆษณา ลิงก์ปลายทาง งบต่อวัน (เพจคือเพจของแคมเปญ ไม่ต้องเลือก) ปุ่ม บันทึกเป็นแอดหยุดไว้ / เปิดใช้ (ยืนยัน) / สร้างใหม่ (ยืนยัน) ทำงานแบบเดียวกับตอนนี้ทุกอย่าง

## 3. ข้อมูล และการย้ายของเดิม

ตาราง `ins_ad_campaign`
- `id uuid pk`, `created_at`, `page_id text not null`, `plan_href text not null`, `name text` (ว่าง = ชื่อแบบประกัน)
- `angles int`, `tones int`, `theme text`, `hint text`, `agent_id uuid` (คนสร้าง)
- RLS เปิด, revoke anon/authenticated, grant service_role แบบ `20260930_wallet.sql`

`ins_content.campaign_id uuid` อ้าง `ins_ad_campaign(id) on delete set null`

ย้ายของเดิม ใน migration เดียวกัน
- ชิ้น `format = 'ad'` ที่มี `fb_page_id`/`page_id` จัดกลุ่มตาม เพจ + `plan_href` เป็นหนึ่งแคมเปญต่อกลุ่ม รวมชิ้นในถังขยะ
- ชิ้นแอดที่ไม่มีเพจไม่ย้าย อยู่ในฐานข้อมูลตามเดิม
- รันซ้ำได้ ไม่สร้างแคมเปญซ้ำ
- `ins_ad_launch` ผูกกับชิ้นอยู่แล้ว ไม่ต้องย้าย

การเขียนแอด: `generateContent` รับ `campaignId` เพิ่ม
มีค่า = ใช้แบบประกัน เพจ มุมขาย โทน โทนสี hint จากแคมเปญ และบันทึกชิ้นพร้อม `campaign_id`
ตัวเขียน `writeAds` การเช็กกฎ และการกันงบเหมือนเดิม
`generateContent` ปฏิเสธ `format: "ad"` ที่ไม่มี `campaignId` (Organic Studio ไม่ส่งแอดมาอีก)

การยิง: `launchAd` เดิม เพจมาจากแคมเปญ

## 4. สิทธิ์ ข้อผิดพลาด การทดสอบ

สิทธิ์: `owner` คนเดียว (รหัส 015495)
- เจ้าของสร้างแคมเปญและยิงแอดได้**ทุกเพจที่เชื่อมกับระบบ** (`myPages()` ของเจ้าของคืนทุกเพจจาก `pageConnections()` อยู่แล้ว) บนบัญชีโฆษณาที่เชื่อมไว้บัญชีไหนก็ได้
- ฝั่ง Meta: บัญชี Facebook ของเจ้าของต้องมีบทบาทลงโฆษณาในเพจนั้น ถ้าไม่มี ขั้นสร้างครีเอทีฟจะพังพร้อมข้อความจาก Meta และหยุดตรงนั้น (การหยุดต่อขั้นเดิม)
- ช่องหน้ารวมและเมนูโผล่เฉพาะเจ้าของ
- `/studio/ads` และ `/studio/ads/[id]` ใช้ `gatePage(..., "owner")`
- ทุก action ของ Ads Studio เรียก `requireStaff("owner")` รวมการเขียนแอดด้วย `campaignId`
- เจ้าของเขียนฟรี ไม่ผ่านกระเป๋าเงิน

ข้อผิดพลาด
- เขียนแอดไม่สำเร็จ: แสดงข้อความ คืนงบที่กันไว้ แบบ Organic Studio
- แคมเปญไม่มี / id ผิด: กลับหน้ารายการ
- เพจของแคมเปญไม่อยู่ในเพจที่เจ้าของเชื่อม: ปุ่มยิงบอกให้เชื่อมเพจก่อน (การตรวจเดิม)

ทดสอบ
- unit: ทุก action ปฏิเสธคนที่ไม่ใช่เจ้าของ; เมนูและหน้ารวมโผล่ Ads Studio เฉพาะเจ้าของ; `generateContent` กับ `campaignId` ใช้ค่าแคมเปญและบันทึก `campaign_id`; `format: "ad"` ไม่มี `campaignId` ถูกปฏิเสธ; Organic Studio ไม่แสดงและไม่นับชิ้นแอด; การจัดกลุ่มของ migration
- เบราว์เซอร์: localhost ด้วยบัญชีเจ้าของเห็นครบ ด้วยบัญชี Nit ไม่เห็นและเข้าไม่ได้
- โปรดักชัน: รัน migration แล้วนับว่าชิ้นแอดที่มีเพจได้แคมเปญครบ แล้วค่อย push

## สิ่งที่ต้องยืนยันก่อนลงมือ

- ชิ้นแอดเก่าที่ไม่มีเพจมีกี่ชิ้น (นับบนโปรดักชันก่อนรัน migration) ถ้ามีมากให้ถามเจ้าของว่าจะผูกกับเพจไหน
- คอลัมน์เพจของ `ins_content` คือ `page_id` หรือ `fb_page_id` สำหรับชิ้นที่ยังไม่โพสต์ (ตรวจตอนเขียน migration)
