# Protection Life (PLB) Brain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A customer who names Protection Life in any bot is taken through a multi-message quotation (who → how much → how long), answered the usual questions in fixed sentences, and never sent the quotation again for nothing.

**Architecture:** Split the one-message pricer (`priceNamedPlan`) into a reader and a pricer. A new rule-only brain (`assistant/plb/answer.ts`, shaped like `answerIShield`) keeps age, sex, sum and term across turns and calls the pricer directly, so every figure still comes from the rate table through one path. The dispatcher routes to it when the customer names PLB. No model, no migration, no menu change.

**Tech Stack:** TypeScript, Next.js, vitest (`npx vitest run tests/calc tests/chat`), `npx tsc --noEmit -p .`.

**Spec:** `docs/superpowers/specs/2026-10-07-plb-brain-design.md` (approved 2026-10-07).

## Global Constraints

- PLB is reached **by name only**: not in the greeting menu (`DOORS` in `choose.ts`), the welcome editor, the LINE rich menu or the ads.
- **No intro picture** for PLB: the brain's answers are not marked `introFor`.
- **No riders** (AP, ECARE, MEB) in chat. **One person per quotation** (a message naming two prices the first and says the other can be sent next).
- Every figure comes from the rate table via `quote()`; the brain never computes a premium.
- Terms are `PLB05`, `PLB10`, `PLB12`, `PLB15`, labelled "ชำระเบี้ย N ปี" (`registry.ts`).
- **No migration.** `page_welcome.product`'s CHECK constraint is untouched, so `/admin/welcome` must not be able to save `plb` (Task 5).
- Waiting period for PLB: the bot says it has no confirmed answer and the admin will check. The owner has confirmed only Life Protect ("คุ้มครองทันทีหลังกรมธรรม์อนุมัติ").
- `git add` explicit paths only. Baseline: `tests/chat/session-turn.test.ts` already fails on `main`; every other test must pass.
- Customer-facing text is Thai, "ครับ", speaking as the Page's admin ("ผม").

## Review Focus

1. The real message "สอบถามเงื่อนไขเพิ่มเติมครับ ต้องตรวจสุขภาพหรือไม่ มีระยะเวลารอคอยหรือไม่" after a PLB quotation: one answer carrying both the health declaration and the waiting-period handover, no card (Task 4).
2. "ชาย 15 ปี" is a 15-year-old, not the 15-year term; "PLB ชาย 35 จ่าย 10 ปี" is age 35 and term 10 (Task 4).
3. A sum under the plan's minimum, or an age outside its range: the engine's own refusal sentence, and the next message ("ทุน 1 ล้าน") prices with the person kept (Task 4).
4. A small sum whose monthly instalment is under the company's floor prints no "รายเดือน" line (Task 4).
5. In a PLB conversation, "ประกันชีวิต ลดหย่อนภาษีได้ไหม" stays on PLB — only an explicit Life Protect name moves it away. *This is one addition beyond the spec; the spec says switching is "as today", and today the generic words would hijack the chat.* (Task 5)

**Files:**

**Interfaces:**
- Consumes: Task 1 (`readPlanAsk`, `pricePlan`, `variantAskedFor`, `PlanAsk`), Task 2 (`pricedAnswer`), Task 3 (`plbFaqAnswer`, `PLB_WAITING`, `asksWaiting`), and from `../common`: `saysUnwell`, `HEALTH_DECLARATION`, `asksAboutCompany`, `aboutCompany`, `wantsToBuy`, `handOverForm`, `saysFormDone`, `FORM_RECEIVED`, `thanksOnly`, `THANKS_REPLY`, `stalls`, `stallReply`, `peopleIn`, `ageIn`, `sexIn`, `coverIn`, `type Reply`; `writtenFor`, `type Channel` from `../channel`; `GuideItem` from `@/lib/copilot/guide`.
- Produces:
  - `export const PLB = "PLB"`, `export const PLB_LABEL = "Protection Life (PLB)"`.
  - `export interface PlbSlots { product: "plb"; age?: number; sex?: "M" | "F"; sumAssured?: number; variant?: string; formSent?: true }`.
  - `export type PlbAnswer = Reply & { slots: PlbSlots; guide?: GuideItem[] }`.
  - `export function answerPlb(asked: string, previous: PlbSlots | null, channel?: Channel): PlbAnswer` — synchronous; `channel` defaults to `"web"`.
- Behaviour, in this order, earlier wins (the spec's §2): (1) `saysUnwell` → `HEALTH_DECLARATION`, followed by a blank line and `PLB_WAITING` when `asksWaiting(asked)`; (2) `asksAboutCompany` → `aboutCompany`; (3) `wantsToBuy(asked, quoted)` → `handOverForm`, sets `formSent`; (4) `formSent && saysFormDone` → `FORM_RECEIVED`, `formDone: true`; (5) `thanksOnly` → `THANKS_REPLY`; (6) `stalls` → `stallReply(quoted)`; (7) `plbFaqAnswer` — and when `quoted` and the message has no digit and none of `เบี้ย|ราคา|เท่าไ|ทุน`, that answer is the whole reply; (8) else merge `readPlanAsk(asked, PLB)` into the slots (what is said now wins: a new sum or term re-prices with the rest kept; with no pair from `peopleIn`, take a lone `ageIn`/`sexIn` only for a slot still empty) and call `pricePlan`. Complete → `pricedAnswer(...)`, `priced: true`, slots carry sum and term. Incomplete → the gap reply, slots as merged. Both set `replies` (the `guide` labels) and `guide`. A second person named adds one line: "อีกท่านบอกได้เลยครับ เดี๋ยวคิดให้". `quoted` means age, sex, sum and term are all held.
